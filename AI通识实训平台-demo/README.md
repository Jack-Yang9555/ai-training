# AI 通识实训平台 Demo

面向开发人员的独立高保真原型。一级页面覆盖实训总览、通用任务清单、培训人员与分组、成果中心和任务工作台；选修任务选择已合并进任务清单，M01—M12、E01—E06 均已实现专属可操作工作台，G01—G03 均已实现不计分的阶段验收闭环。

## 运行

```powershell
npm install
npm run dev
```

浏览器打开 Vite 输出的本地地址。生产构建：

```powershell
npm run typecheck
npm test
npm run build
```

如果当前 PowerShell 提示无法识别 `node` 或 `npm`，可以直接运行：

```powershell
powershell -ExecutionPolicy Bypass -File .\启动AI通识实训平台-demo.ps1
```

脚本会优先使用系统 Node.js；若没有加入 `PATH`，会自动查找当前用户目录下 WorkBuddy 自带的 Node.js，然后启动 Demo。

## 推荐演示路径

1. 从实训总览查看三日路径和总体进度。
2. 点击右上角教师信息查看所在组别及全部组员，再点击其后的“人员分组”，载入或选择 CSV，检查人员基本信息、分组和当前演示人员；人员档案不设置任务角色。
3. 进入任务清单查看 12 项必修、每组两项有序选修和 3 次阶段验收；基础日程为 18 小时。
4. 在“选修任务库”中以当前教研组共同选择两个不同任务并确定顺序：第 1 项安排在第二天、第 2 项安排在第三天。每位组员需分别确认本人执行顺序；选择变化会清空全组确认，跨组选择互不影响。
5. 在任务清单中可进入全部 M01—M12、E01—E06 与 G01—G03 工作台。多数任务按自身规则独立推进；M10 必须读取当前教师本人有效 M09，M11 必须读取本人有效 M10，G03 必须读取本人当前 M09—M11 证据，M12 正式验收必须汇总当前教师 10 类有效成果。
6. 完成 M01 的提问、核验、修正、小组复核、评分和成果预览；复核对象来自导入名单中的同组人员，任务角色仅在当前任务临时选择。
7. 返回第一天任务清单，直接进入 M02“多模型教学结果对比与选择”；M01 是否通过不影响 M02 使用。
8. 在 M02 先同时运行两个匿名模型，再完成 8 项任务遵循检查和逐项引导的 10 项五维盲评；盲评页始终并列展示 A/B 两份完整输出，学员可横向比较内容，用带中文含义的五档评分卡选择分数，并在当前模型中直接点击输出段落作为证据；当前项完整后才能进入下一项。
9. M02 的“五维盲评”和“选择与修正”合并为同一个第 4 步：提交盲评后在当前页揭晓名称并锁定评分，随后点击一张模型卡；系统直接带出该模型的五维盲评记录，勾选两条作为决策依据，自动关联另一个模型作为对比对象，再补充综合结论和一处人工修正。完成后进入小组共评，查看同组成员的确定性模拟成果并提交共同结论。
10. M02 达到 8 分且四项核心要求全部通过后，在“成果中心”确认 M01 三项、M02 四项过程成果分别自动归档；这些过程成果不会重复计入十类个人最终成果。
11. 可随时独立进入 M03，先阅读真实对话中的完整示例，再从空白消息框自行输入“角色/任务、背景、输入、约束、输出格式、质量标准”六项名称和内容；右侧只实时识别完成情况，不代写。完整确认材料权属和隐私后发送，生成并锁定第一版课堂练习包（V1）。
12. 从学生基础、题量、难度、课堂时长、输出格式中选择一项生成 V2；在版本比较页分别关联 V1/V2 输出段落，完成材料范围和教学目标核验。
13. 选择同组成员的确定性模拟版本成果，提交三项清晰度检查和可执行建议；提交验收后确认 M03 通过，并在成果中心归档恰好三项 M03 过程成果。
14. 直接进入 M04，确认课程、学情、目标、材料、真实工作任务及 45—90 分钟课堂条件，生成结构化教案草稿。
15. 核对 3 个目标、全部活动与课堂限制，分别保存难度、活动、专业表述三类修改；完成同组教案互评和教师确认后提交验收，归档三项 M04 教案成果。
16. 独立进入 M05，使用任务内命题输入或可选读取 M04 当前成果，生成恰好 8 道题并逐题核验答案、解析、依据、难度、干扰项和评分要点。
17. 人工修订两道不同题目，完成同组至少一题交叉核验和教师确认；提交验收后归档“课堂题目包、题目核验依据与修改记录”两项 M05 成果。
18. 可在任意时点独立进入 G01；当前教师优先读取已有 M01—M05 本地成果，缺项使用明确标注且仅在 G01 内有效的演示成果。
19. 依次核对三项固定成果目录、每位成员的一处 AI 错误与教师修正、每位成员的一次教案或题目包交叉检查，以及不少于 8 项且覆盖事实、引用、安全、目标、答案五类的清单和个人贡献。
20. 提交阶段验收，确认页面不展示数值评分；通过后成果中心恰好归档三项 G01 成果，阶段验收完成数增加，普通计分任务完成数不变。
21. 切换到第二天，可独立进入 M06，使用任务内输入或可选读取 M04 当前教师确认版；生成 7 页课件和 170 字讲解稿，逐页检查并完成至少 1 处实质修改，使用预设形象/音色/字幕生成 54 秒可播放本地视频。
22. 可独立进入 M07，使用固定 A01—A20 匿名虚拟成绩表；完成数据检查、确定性统计、人工复算、结论审校、临时分层任务、同组复核和教师确认。
23. 可独立进入 M08，使用任务内已核验材料或可选读取 M04/M06 当前成果；生成 V0，经两轮自然语言迭代形成 V1/V2，下载单文件并完成电脑、手机、离线测试，再由当前同组其他成员按学生视角测试并修正至少 1 处。
24. 提交 M08 验收后确认只归档 1 个“交互式教学网页”；修改当前材料、迭代、测试或确认后，旧验收历史保留但当前通过失效。
25. 可独立进入 G02；核对当前小组四类成果目录，完成一页式展示和至少 1 个在线互动，确认 2 条跨组模拟反馈，应用至少 1 条形成可核对修改，并确认全员贡献。
26. G02 四项条件全部通过后，成果中心恰好归档“小组多模态教学成果展示页、同伴反馈与修改记录、成员贡献清单”三项；G02 不显示数值评分，M07 不属于验收材料。
27. 切换到第三天，可独立进入 M09；载入 4 份已审核课程样例，或读取本机 `.txt/.md` 文件。本机文件只在当前浏览器处理，不上传服务器；最终应保留 2—5 份名称、来源、版本、适用范围和授权状态完整的有效资料。
28. 对每份资料分别处理重复、过期、缺页和错误版本四类问题，建立可定位原文的本地片段索引 v0；运行同一组 5 道有据题和 4 道边界题首测，逐题打开来源片段并完成教师核验。首测会稳定暴露至少 1 个可修正问题，不会一键全部通过。
29. 从首测问题中保存至少 1 条具有修改前、修改后和依据的实质修正，然后用完全相同的 9 个题号复测。复测 9 / 9 符合预期后，选择当前同组其他成员完成至少 1 道边界测试，再确认资料范围、来源、回答边界、安全和最终维护责任，形成课程知识库 v1.0 并提交评分。
30. M09 通过后，任务归档恰好保存“课程知识库 v1.0 及来源清单”和“课程知识库 9 项问答测试报告和修正记录”两项过程成果；个人最终成果中心仍只占用“课程知识库和来源清单”1 个槽位。修改来源、规则、题目、小组测试或教师确认后，旧验收历史保留，但当前通过失效。

   - 进入 M10，绑定本人 M09 当前知识库，载入并核对角色、对象、任务、知识、流程和边界六要素，配置不可删除或调序的“了解问题—检索材料—引用解释—检查理解”四步流程，以及超范围、代做、安全、最终成绩、敏感数据五类边界。
   - 运行正常问题与边界问题两种预览，正常回答必须打开可定位来源，边界回答必须停止猜测、禁止虚假引用并转交教师；选择同组其他成员与临时角色完成明确披露的模拟互评，至少保存 1 条有前后差异和依据的实质修改，再逐项确认教师责任并提交五维验收。M10 恰好归档 2 项任务证据，但个人成果仍只占“课程 AI 助教”1 个槽位。
   - 进入 M11，使用本人 M10 当前助教建立环形双向配对：本人测试同组他人，也接受上游成员测试。连续发送正常、含糊、超范围、要求代做、安全与评价综合五类固定问题；首测稳定呈现 3 / 5，并保留 Q02、Q05 的可追溯问题，不一键全对。
   - 对五题逐题判断并标注问题，依据首测保存回答流程与角色边界实质修改；用完全相同的题号、题文、配对和助教快照复测到 5 / 5，逐题人工确认后提交五维验收。M11 恰好归档 2 项任务证据，并合并到 1 个个人成果槽位。
   - 完成 M12 后进入 G03。当前教师必须提供真实且当前有效的 M09—M11 证据；其他组员使用确定性模拟证据并在页面披露。小组逐人确认“测试他人/接受测试”双向矩阵，至少闭合 1 条问题—修改—负责人—同题复测链，准备有据回答、含糊追问、超范围转交三类场景。
   - G03 以 A/B 两批完成两轮展示，每轮记录 3 分钟演示与 2 分钟在线答问，并逐人确认贡献。四项条件全部通过后才归档“测试与修改报告、现场演示材料、成员贡献记录”恰好 3 项小组成果；页面不显示数值评分。

52. 非计分预演提供 10 个醒目标记的只读样例，让教师完整练习三阶段编排、可追溯错误修正、助教有据回答与越界转交、四入口联调、教师修改、同路径复测、安全复核、小组展示和最终确认。首轮会从当前衔接实际判出 3 / 4，只有保存相关实质修改后复测才达到 4 / 4。
53. 预演结果只显示 5 / 5 项规则映射，不生成数值成绩、正式通过或成果归档，也不增加平台总体进度；进入预演不会清除已有正式确认、验收或归档状态。正式模式在 10 类成果及全部证据齐备后，按五维 0—2 分、总分不低于 8 分和“专业证据、人工迭代、安全”三项 2 分硬门槛验收；正式小组反馈只能选择当前真实同组其他成员，由当前教师据实本地代录并明确标注“非实时提交”；通过后只归档“成果目录、使用说明、人工修改记录”三项整合成果，不新增第 11 类个人成果。

## 正式服务接入边界

- 学员浏览器只调用业务服务端，不保存或直连 Dify API Key。
- 服务端实现同一 `M02ModelRunner` 接口，调用一个 Dify Workflow；统一输入锁定课程材料与提示词，通过两个模型分支生成结果，并把两份输出规范化为同一 `runId` 下的匿名 A/B。
- 任一分支失败时整批标记失败，学员只能重新运行整个批次；真实模型映射由服务端保留，盲评提交后再通过 reveal 接口返回。
- 接口可按部署条件使用阻塞或流式调用，并另行对接运行状态与规范化输出。设计依据见 [Dify Workflow 快速入门](https://docs.dify.ai/en/quick-start) 和 [Dify Workflow 调用接口](https://docs.dify.ai/en/develop-plugin/features-and-specs/advanced-development/reverse-invocation-app)。
- M03 通过 `M03PromptRunner.run({ participantId, version, snapshot })` 隔离生成实现；Demo 使用确定性本地运行器，正式系统可在不改变页面和领域数据的前提下替换为业务服务端实现。
- M03 的课程材料、编译提示词和教师标识只应提交给受控业务服务；模型密钥不得写入浏览器存储、Vite 环境变量或运行快照。
- M04 通过 `M04LessonPlanRunner.run({ participantId, input })` 隔离教案生成；M05 通过 `M05QuestionRunner.run({ participantId, input })` 隔离题目包生成。正式系统可分别替换为受控业务服务，保持 AI 草稿、人工审校和教师确认三层版本边界。
- M09 通过本地确定性规则完成文本片段索引、来源定位和同题首测/复测；正式系统需替换为受控文档解析、知识库和检索服务，但仍必须保留资料版本、来源片段、知识边界和教师最终确认。
- E02 通过 `LocalE02DraftRunner` 隔离任务书初稿生成；正式系统可替换为受控业务服务，但仍须保留规范版本、AI 原稿、教师工作稿、同组复核、实质修正和教师最终责任六层可追溯证据。
- E03 通过 `LocalE03FindingRunner` 隔离课堂发现初稿生成；正式系统可替换为受控业务服务，但仍须保留原记录定位、事实与解释边界、AI 原稿、同组反馈、人工修订和教师最终责任。
- E04 通过 `LocalE04GraphRunner` 隔离课程图谱初稿生成；正式系统可替换为受控业务服务，但节点与关系必须保留稳定编号、来源位置、方向复核和人工修正历史。
- E05 通过 `LocalE05MappingRunner` 隔离岗位任务、课岗映射和建议初稿生成；正式系统可替换为受控业务服务，但课程与岗位双侧证据、映射状态、差距建议、网页版本和人工修正必须保持可追溯。
- E06 通过 `LocalE06LiteratureRunner` 隔离文献梳理初稿生成；正式系统可接入受控文献数据库与检索服务，但必须保留文献元数据、原文定位、观点边界、引用核验和教师最终判断，禁止由模型补造来源。
