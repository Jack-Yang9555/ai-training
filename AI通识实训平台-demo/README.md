# AI 通识实训平台 Demo

面向开发人员的独立高保真原型。一级页面覆盖实训总览、通用任务清单、培训人员与分组、成果中心和可扩展任务框架；选修任务选择已合并进任务清单，M01—M08 已实现完整交互与评分闭环，G01、G02 已实现不计分的阶段验收闭环。

## 运行

```powershell
npm install
npm run dev
```

浏览器打开 Vite 输出的本地地址。生产构建：

```powershell
npm run typecheck
npm test
npm run build
```

如果当前 PowerShell 提示无法识别 `node` 或 `npm`，可以直接运行：

```powershell
powershell -ExecutionPolicy Bypass -File .\启动AI通识实训平台-demo.ps1
```

脚本会优先使用系统 Node.js；若没有加入 `PATH`，会自动查找当前用户目录下 WorkBuddy 自带的 Node.js，然后启动 Demo。

## 推荐演示路径

1. 从实训总览查看三日路径和总体进度。
2. 点击右上角教师信息查看所在组别及全部组员，再点击其后的“人员分组”，载入或选择 CSV，检查人员基本信息、分组和当前演示人员；人员档案不设置任务角色。
3. 进入任务清单查看 12 项必修、后两天选修时段和 3 次阶段验收；基础日程为 18 小时。
4. 在“选修任务库”中为第二天、第三天分别选择至少 1 项任务（均可多选且不能跨天重复），观察对应 DAY 与成果中心同步更新；每天第一项纳入基础日程，增选项作为当天自主任务。
5. 在任务清单中按需进入已实现的 M01—M08、G01 或 G02；各任务按自身步骤规则推进。M04—M08、G01、G02 不要求推荐顺序中的任务先完成。
6. 完成 M01 的提问、核验、修正、小组复核、评分和成果预览；复核对象来自导入名单中的同组人员，任务角色仅在当前任务临时选择。
7. 返回第一天任务清单，直接进入 M02“多模型教学结果对比与选择”；M01 是否通过不影响 M02 使用。
8. 在 M02 先同时运行两个匿名模型，再完成 8 项任务遵循检查和逐项引导的 10 项五维盲评；盲评页始终并列展示 A/B 两份完整输出，学员可横向比较内容，用带中文含义的五档评分卡选择分数，并在当前模型中直接点击输出段落作为证据；当前项完整后才能进入下一项。
9. M02 的“五维盲评”和“选择与修正”合并为同一个第 4 步：提交盲评后在当前页揭晓名称并锁定评分，随后点击一张模型卡；系统直接带出该模型的五维盲评记录，勾选两条作为决策依据，自动关联另一个模型作为对比对象，再补充综合结论和一处人工修正。完成后进入小组共评，查看同组成员的确定性模拟成果并提交共同结论。
10. M02 达到 8 分且四项核心要求全部通过后，在“成果中心”确认 M01 三项、M02 四项过程成果分别自动归档；这些过程成果不会重复计入十类个人最终成果。
11. 可随时独立进入 M03，先阅读真实对话中的完整示例，再从空白消息框自行输入“角色/任务、背景、输入、约束、输出格式、质量标准”六项名称和内容；右侧只实时识别完成情况，不代写。完整确认材料权属和隐私后发送，生成并锁定第一版课堂练习包（V1）。
12. 从学生基础、题量、难度、课堂时长、输出格式中选择一项生成 V2；在版本比较页分别关联 V1/V2 输出段落，完成材料范围和教学目标核验。
13. 选择同组成员的确定性模拟版本成果，提交三项清晰度检查和可执行建议；提交验收后确认 M03 通过，并在成果中心归档恰好三项 M03 过程成果。
14. 直接进入 M04，确认课程、学情、目标、材料、真实工作任务及 45—90 分钟课堂条件，生成结构化教案草稿。
15. 核对 3 个目标、全部活动与课堂限制，分别保存难度、活动、专业表述三类修改；完成同组教案互评和教师确认后提交验收，归档三项 M04 教案成果。
16. 独立进入 M05，使用任务内命题输入或可选读取 M04 当前成果，生成恰好 8 道题并逐题核验答案、解析、依据、难度、干扰项和评分要点。
17. 人工修订两道不同题目，完成同组至少一题交叉核验和教师确认；提交验收后归档“课堂题目包、题目核验依据与修改记录”两项 M05 成果。
18. 可在任意时点独立进入 G01；当前教师优先读取已有 M01—M05 本地成果，缺项使用明确标注且仅在 G01 内有效的演示成果。
19. 依次核对三项固定成果目录、每位成员的一处 AI 错误与教师修正、每位成员的一次教案或题目包交叉检查，以及不少于 8 项且覆盖事实、引用、安全、目标、答案五类的清单和个人贡献。
20. 提交阶段验收，确认页面不展示数值评分；通过后成果中心恰好归档三项 G01 成果，阶段验收完成数增加，普通计分任务完成数不变。
21. 切换到第二天，可独立进入 M06，使用任务内输入或可选读取 M04 当前教师确认版；生成 7 页课件和 170 字讲解稿，逐页检查并完成至少 1 处实质修改，使用预设形象/音色/字幕生成 54 秒可播放本地视频。
22. 可独立进入 M07，使用固定 A01—A20 匿名虚拟成绩表；完成数据检查、确定性统计、人工复算、结论审校、临时分层任务、同组复核和教师确认。
23. 可独立进入 M08，使用任务内已核验材料或可选读取 M04/M06 当前成果；生成 V0，经两轮自然语言迭代形成 V1/V2，下载单文件并完成电脑、手机、离线测试，再由当前同组其他成员按学生视角测试并修正至少 1 处。
24. 提交 M08 验收后确认只归档 1 个“交互式教学网页”；修改当前材料、迭代、测试或确认后，旧验收历史保留但当前通过失效。
25. 可独立进入 G02；核对当前小组四类成果目录，完成一页式展示和至少 1 个在线互动，确认 2 条跨组模拟反馈，应用至少 1 条形成可核对修改，并确认全员贡献。
26. G02 四项条件全部通过后，成果中心恰好归档“小组多模态教学成果展示页、同伴反馈与修改记录、成员贡献清单”三项；G02 不显示数值评分，M07 不属于验收材料。

## 演示边界

- M01 的 AI 回答、学员身份和小组成员为确定性模拟数据；小组待复核成果由教师修正动态生成。
- M02 当前使用确定性本地 `M02ModelRunner`，一次运行创建同一 `runId` 下的 A/B 两份结构化结果；课程材料、提示词和模型组合均锁定，学员端在盲评提交前不接收真实模型名称。
- 不调用真实模型，不连接账号、数据库或后端接口。
- 培训人员 CSV 只在浏览器本地读取和预览；确认导入后保存在本地 `localStorage`，不会上传文件。
- M01 被复核对象读取导入名单中的同组人员；由于当前没有多人提交后端，组员成果仍由教师修正按回答场景确定性映射，并在页面标注为模拟边界。
- M01 进度保存在浏览器 `localStorage` 的 `qijing-training-demo:m01:v1` 键中；M02 使用独立的 `qijing-training-demo:m02:v3`，按 `participantId` 隔离个人评价，并会在首次读取时迁移旧版 `m02:v2` 三模型进度或更早的 `m02:v1` 选择记录。
- M03 使用 `qijing-training-demo:m03:v2` 按 `participantId` 保存教师原始对话消息、解析后的角色/任务、背景、输入、约束、输出格式、质量标准六项快照，以及两版运行、核验证据、小组互评和验收历史；旧 `v1` 数据只迁移设计草稿和验收历史，旧版运行成果失效。修改实质数据后旧验收快照保留，但不再计为当前有效成绩。
- M04 使用 `qijing-training-demo:m04:v1` 按 `participantId` 保存教案输入、AI 草稿、人工审校、同组互评、教师确认版和验收历史。
- M05 使用 `qijing-training-demo:m05:v1` 按 `participantId` 保存命题输入、8 道题草稿、逐题审校、人工修订、同组互评、教师确认题目包和验收历史。
- M06 使用 `qijing-training-demo:m06:v1` 按 `participantId` 保存任务内输入、可选 M04 来源、AI 原始课件/讲解稿、逐页核验、实质修改、预设数字人配置、54 秒本地视频、同组互评、教师确认组合成果和验收历史。实质内容变化后旧验收历史保留，但当前确认和通过失效。
- M07 使用 `qijing-training-demo:m07:v1` 按 `participantId` 保存任务内课程情境、可选 M06 来源、固定虚拟数据检查、确定性统计、至少 3 个教师复算、证据结论审校、三个临时任务、同组数字复核、教师确认成果和验收历史。只使用匿名虚拟数据，不输出个人排名或固定能力标签。
- M08 使用 `qijing-training-demo:m08:v1` 按 `participantId` 保存任务内或可选 M04/M06 输入、V0/V1/V2、两轮修改、下载与双端/离线测试、同组学生测试修正、教师确认网页和验收历史。最终网页为不依赖外部资源的单文件 HTML。
- G01 使用 `qijing-training-demo:g01:v2` 按 `groupId` 保存人员名单指纹、M01—M05 五类材料、错误修正、交叉检查、五类核验清单、个人贡献和验收历史。
- G02 使用 `qijing-training-demo:g02:v1` 按 `groupId` 保存人员与成果指纹、四类成员成果目录、一页式展示、在线互动、跨组反馈、反馈修改、全员贡献、三项成果快照及初验/补验历史。当前教师缺项与未实现首个选修只使用任务内演示项，其他成员为确定性模拟摘要，均不反写个人任务。
- 顶部“重置演示数据”会清除本地 M01、全部教师的 M02—M08 进度和所有小组 G01、G02 数据。
- M09—M12、E01—E06、G03 已建立一级框架、推荐顺序和成果契约；未实现任务不会生成虚假完成状态。
- 成果中心通过 `buildTrainingPortfolio` 聚合任务完成状态和成果提交；后续任务只需在任务目录声明 `outputs`，并在实现后传入标准 `TaskArtifactSubmission`，即可复用同一自动归档流程。

## 正式服务接入边界

- 学员浏览器只调用业务服务端，不保存或直连 Dify API Key。
- 服务端实现同一 `M02ModelRunner` 接口，调用一个 Dify Workflow；统一输入锁定课程材料与提示词，通过两个模型分支生成结果，并把两份输出规范化为同一 `runId` 下的匿名 A/B。
- 任一分支失败时整批标记失败，学员只能重新运行整个批次；真实模型映射由服务端保留，盲评提交后再通过 reveal 接口返回。
- 接口可按部署条件使用阻塞或流式调用，并另行对接运行状态与规范化输出。设计依据见 [Dify Workflow 快速入门](https://docs.dify.ai/en/quick-start) 和 [Dify Workflow 调用接口](https://docs.dify.ai/en/develop-plugin/features-and-specs/advanced-development/reverse-invocation-app)。
- M03 通过 `M03PromptRunner.run({ participantId, version, snapshot })` 隔离生成实现；Demo 使用确定性本地运行器，正式系统可在不改变页面和领域数据的前提下替换为业务服务端实现。
- M03 的课程材料、编译提示词和教师标识只应提交给受控业务服务；模型密钥不得写入浏览器存储、Vite 环境变量或运行快照。
- M04 通过 `M04LessonPlanRunner.run({ participantId, input })` 隔离教案生成；M05 通过 `M05QuestionRunner.run({ participantId, input })` 隔离题目包生成。正式系统可分别替换为受控业务服务，保持 AI 草稿、人工审校和教师确认三层版本边界。

## 代码结构

- `src/data/`：任务、AI 回答、组员和核验清单的模拟数据。
- `src/logic/`：M01 无 UI 依赖的校验、总体判断和评分纯函数。
- `src/m02/`：M02 数据契约、结构化结果、校验评分、模拟组员成果和按人员隔离存储。
- `src/m03/`：M03 六格快照、单变量校验、证据评分、模拟组员成果、验收历史和按人员隔离存储。
- `src/m04/`：M04 教案类型、人工审校、五维评分、模拟组员成果、确认版与按人员隔离存储。
- `src/m05/`：M05 题目包类型、逐题审校、人工修订、五维评分、模拟组员成果、确认版与按人员隔离存储。
- `src/m06/`：M06 课件、讲解稿、预设数字人、本地视频、人工修改、互评、评分和按人员隔离存储。
- `src/m07/`：M07 匿名虚拟数据、确定性统计、数字复核、证据结论、临时分层任务、评分和按人员隔离存储。
- `src/m08/`：M08 单文件网页生成、两轮迭代、浏览器与同组学生测试、评分和按人员隔离存储。
- `src/g01/`：G01 小组成果类型、逐项阶段验收规则、成果指纹、初验/补验历史和按小组隔离存储；不包含数值评分。
- `src/g02/`：G02 多模态成果目录、展示互动、跨组反馈修改、成员贡献、阶段验收历史和按小组隔离存储；不包含数值评分。
- `src/services/`：可替换的 M02 多模型、M03 提示词、M04 教案和 M05 命题运行适配器；当前均为本地实现。
- `src/storage/`：版本化本地进度读写。
- `src/training/`：通用任务目录、分组配置、推荐顺序、路由、全局进度与成果契约。
- `src/components/`：实训壳层、划词标注器和通用反馈组件。
- `src/pages/`：任务清单、M01/M02 六步页面、M03—M08 七步工作台及 G01、G02 六步阶段验收工作台。
- `tests/`：规则单元测试和关键页面交互测试。
